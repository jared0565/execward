# Task 0.1.2: Dynamic Workers status, limits and pricing

Checked 2026-11-22 against Cloudflare's developer docs. Every figure below is quoted from the
page linked beside it. Nothing here was measured by running code.

**Decision: go** (owner, 2026-11-22), as recommended. Dynamic Workers fit the sandbox role, on the Workers Paid plan. Four
findings change how ExecWard must be built; they are listed under "What this changes".

## Status

| Question | Finding | Source |
|---|---|---|
| Release status | Open beta since 24 March 2026, "for all paid Workers users". I found no general-availability announcement, so treat it as still beta. | [Changelog, 24 March 2026](https://developers.cloudflare.com/changelog/post/2026-03-24-dynamic-workers-open-beta/) |
| Plan needed | "Dynamic Workers are currently only available on the Workers Paid plan." | [Dynamic Workers pricing](https://developers.cloudflare.com/dynamic-workers/pricing/) |
| Plan price | Workers Paid has "a minimum charge of $5 USD per month for an account". | [Workers pricing](https://developers.cloudflare.com/workers/platform/pricing/) |

## Limits

| Limit | Finding | Source |
|---|---|---|
| CPU time | Uses the plan limit by default: 30 seconds, configurable up to 5 minutes. Can be lowered per run with `limits: { cpuMs }`; over the limit, the Dynamic Worker "immediately throws an exception". | [Custom resource limits](https://developers.cloudflare.com/dynamic-workers/usage/limits/), [Workers limits](https://developers.cloudflare.com/workers/platform/limits/) |
| Subrequests | 10,000 per request on Paid. Can be lowered per run with `limits: { subRequests }`. | Same pages |
| Memory | 128 MB per isolate, the Workers limit. The custom limits cover CPU time and subrequests only, so memory cannot be set lower. | [Workers limits](https://developers.cloudflare.com/workers/platform/limits/) |
| Wall-clock time | No wall-clock limit is offered for a Dynamic Worker. Cloudflare's own example stops waiting with a five-second timer in the host Worker, "so the generated code cannot change it". | [Build an AI code interpreter](https://developers.cloudflare.com/sandbox/get-started/build-an-ai-code-interpreter/) |
| Concurrency | 4 distinct Dynamic Workers with in-flight requests per Worker request; 10 inside a Durable Object. | [Dynamic Workers limits](https://developers.cloudflare.com/dynamic-workers/platform/limits/) |
| Network | `globalOutbound: null` makes `fetch()` and `connect()` throw. A Dynamic Worker given no `env` can reach nothing else. | [Egress control](https://developers.cloudflare.com/dynamic-workers/usage/egress-control/) |
| Local development | `wrangler dev` runs code in a local `workerd` process, "which is not a hardened sandbox", and configured limits are "only enforced when deployed to Cloudflare's network, not in local development". | [Wrangler dev](https://developers.cloudflare.com/workers/wrangler/commands/workers/), [Wrangler configuration](https://developers.cloudflare.com/workers/wrangler/configuration/) |

## Pricing

| Dimension | Included each month | Beyond that |
|---|---|---|
| Unique Dynamic Workers created | 1,000 | $0.002 per Dynamic Worker per day |
| Requests | 10 million | $0.30 per million |
| CPU time | 30 million CPU milliseconds | $0.02 per million CPU milliseconds |

Source: [Dynamic Workers pricing](https://developers.cloudflare.com/dynamic-workers/pricing/). The
created-daily charge has been billed since 26 May 2026.

A Dynamic Worker is "uniquely identified by its Worker ID and code — if either changes, it counts
as a new Dynamic Worker". Each model-written script is new code, so I assume every ExecWard run
counts as one created Dynamic Worker. That assumption is not confirmed for one-off `load()` calls.

**Price per run, on that assumption:** about $0.002 once past the first 1,000 runs in a month.
Requests and CPU add almost nothing at this scale: 50 ms of CPU costs $0.000001. Example: 100
runs a day is about 3,000 a month, so 2,000 billable runs, or about $4 a month on top of the
$5 plan.

## What this changes

1. **Workers Paid ($5 a month) is needed from the first sandbox test in Phase 1**, not only at
   launch. Limits and isolation are enforced only on Cloudflare's network.
2. **The adversarial suite's escape and limit cases must run against a deployed test Worker.**
   A local run proves behaviour, not isolation. This affects tasks 0.3.2, 1.2.2 and 1.2.8.
3. **FR-4's memory limit is fixed at 128 MB.** ExecWard can test that a script over it is
   stopped, but cannot choose a lower number.
4. **FR-4's wall-clock and call-count limits must be enforced by ExecWard**, in the host Worker
   and the broker. The platform's `subRequests` limit counts network subrequests, which are
   blocked anyway; whether it also counts calls to the broker's binding is not stated.
   (As built, both are enforced by the executor in the host Worker, and there is no
   binding: see docs/decisions/0.1.3-executor-interface.md.)

## Still unknown

- Whether Dynamic Workers have left beta since March 2026.
- Whether a one-off `load()` counts toward "created daily" exactly as assumed above.
- Whether `subRequests` counts calls made through a custom binding.
- What a script sees when it exceeds 128 MB: the exact error is not documented on these pages.
