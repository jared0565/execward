## A fault in the first fix for F4, found on production the same day

The first fix sent the output as JSON text. But the material is itself JSON, so that
text was a string inside it: the number 5 reached the reviewer as `"5"`, in quotes, and
the new instructions said quotes mean text. About an hour after it was deployed, a live
check returned 5 for "The result is the number 5" and was blocked. The tests had
compared what the code built with what the code was meant to build, and not with what
a reader of the material would see.

Fixed the same day: the output is put into the material as a value, so a number is a
number there. Only an output too long to send whole is sent as text, and a pass on that
does not count. A test now reads the material as text and fails if a number is in
quotes. Between the two deploys (about 05:07 to 06:30 UTC) the reviewer on production
could wrongly block a right numeric result; one run was, and it was this check.

## Limits

- **The fixes were not reviewed by the second family.** One pass was approved.
- **Left open by F1:** switching between projects that do have a record still gives
  each its own retry limit and spend cap. There are two such projects. No limit across
  projects exists.
- **Left open by F3:** the runner and the script share one set of JavaScript built-ins.
  A script can change how its own run is reported in ways that only mislead the model
  that wrote it: it cannot reach the host that way. A script that wants to skip an
  assertion can simply not write it.
- **Left open by F4:** the reviewer is sent the result, not the logs. A model can still
  read a JSON `5` and a quoted `"5"` carelessly; no daily case covers the pair.
- **Left open by F5:** tool arguments have no size limit where they enter the host,
  and the final value is built whole inside the sandbox before it is cut. The
  sandbox's own memory limit and the platform's transport limit are what bound both.
- **Left open by F6:** calls counted ahead before midnight and handed back after it
  lower the new day's count, by at most 16 a tool a run.
- **Left open by F7:** one search reads the whole tool list. It has 15 entries.
- **Left open by F8:** the daily check has no budget of its own, and a day lost is not
  tried again.
- **Not reviewable from the source given**, in the reviewer's words: Cloudflare's own
  isolation and transport limits; the Worker's entry point and how sign-in is checked;
  the connector, its token and GitHub's permissions; whether the stored retry count is
  safe when two requests arrive together; the audit log; the release gate; the
  registry and the supply chain; how well the reviewer model resists planted text.
- A model's review is not a penetration test (task G.10).
