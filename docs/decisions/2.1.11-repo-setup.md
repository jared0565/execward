# Task 2.1.11: one command sets a repository up, and checks the setup

Date: 2026-11-26. Traces to: FR-10 (the MCP server for CLIs); the project owner's
request of 2026-11-26.

## The owner's request

Using ExecWard in a second repository had come down to a list of steps for the owner:
check the GitHub App, add the MCP server, add a line to `CLAUDE.md`. The owner's
answer: this should be ExecWard's own job once it is added to a repository. Its first
task there is to check that what it depends on is present and working, to install or
update what is not, and to bring files such as `CLAUDE.md` up to date.

## What was built

    npm run repo:setup -- --repo PATH             set it up, or put right what has drifted
    npm run repo:setup -- --repo PATH --check     look and report; change nothing

Run from this repository, against the folder of another. It goes through these in order
and prints one line for each:

| Step | What it looks at | What it does if it is wrong |
|---|---|---|
| Node | The version running the command | Reports it. It does not install Node |
| Claude Code | The `claude` command answers | Reports it, and stops |
| Repository | The folder is a git repository whose `origin` is on GitHub | Reports it |
| Project record | Production has a record of the project | Adds it, only with `--add-project`, at the class given by `--class` (internal if not given) |
| MCP server | Claude Code has the server for that folder, at the right address | Adds it; replaces one of the same name that points elsewhere |
| Connection | Claude Code reports the server as connected | Says how to sign in. Only a person can |
| CLAUDE.md | The folder's `CLAUDE.md` holds ExecWard's block, naming the project | Writes or replaces the block, and nothing else in the file |
| GitHub App access | Nothing: it cannot see this | Says so, and how to check |

It exits 0 only when every step but the last is right. Running it again changes nothing.

## Choices made

- **The server is added in Claude Code's own settings for that folder,** private to this
  computer (`claude mcp add --scope local`), not in a `.mcp.json` file. Nothing about the
  server is then committed to the other repository.
- **The block in `CLAUDE.md` is marked and versioned.** The command owns what is between
  its two marker lines and nothing outside them. Raising `BLOCK_VERSION` makes every
  repository's block be rewritten the next time the command is run there.
- **The block names the project and says nothing else.** A call that names a project
  with no record is refused, so a model has to be told the name. Anything more would be
  a push towards the tool, which the skill trial (task 2.3.2) is there to measure.
- **Adding a project to production needs `--add-project`.** It writes to the production
  database and its audit log, so it does not happen as a side effect. The same step
  writes the read-only GitHub tools' policy records again, as `npm run setup:github`
  does, which puts back any that was changed.
- **It installs nothing.** The owner asked for dependencies to be installed or updated
  where needed. The two it depends on are Node and Claude Code, each installed in a way
  that belongs to the computer's owner, so the command reports a missing or old one with
  what to do, and does not run an installer. This is less than was asked, on purpose.

## Seen working

2026-11-26, on the owner's website repository. A check-only run reported two things to
fix. A real run added the server and wrote `CLAUDE.md`, and reported "Ready". A second
check-only run reported every step right and exited 0.

## Limits

- **It cannot check the GitHub App's access.** That needs the App's own credential,
  which only the production Worker holds. The report marks the step `unchecked`, never
  `ok`. For the trial repository it was checked by asking ExecWard itself.
- **"Connected" is Claude Code's word.** The command reads it from `claude mcp get`. It
  does not make a call through the server.
- **It is run from this repository, by someone with it checked out.** It is not a
  package another repository can install.
- **Only Claude Code.** Codex and other clients are not set up by it.
- **The `CLAUDE.md` it writes is not committed.** That is the other repository's
  decision.
- The script that runs the real commands is not covered by tests; the part that decides
  is (`test/repo-setup.test.ts`, 30 tests), with made-up commands and files.
