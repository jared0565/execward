# 1.1.4 The weekly advisory check and the 72-hour patch window

Date: 2026-11-22. Requirement: FR-23; Governance: vulnerability intake. Threat-table row 6
(supply chain). Task 1.1.3 made sure a dependency cannot change silently. This task finds
out when a pinned dependency turns out to have a known flaw.

## What runs

`.github/workflows/advisories.yml`, every Monday at 06:17 UTC, and on demand:

1. Installs the pinned tree with `npm ci`.
2. Asks npm for known advisories against it (`npm audit --json`).
3. `scripts/advisory-check.ts` writes the report into the run's summary. That page, kept by
   GitHub for each run, is the log.
4. For each **critical** advisory it opens an issue titled
   `Critical advisory in <package>: <advisory id>`, with a **patch-by time 72 hours after
   the check found it**, and the run fails. A failed scheduled run notifies the repository
   owner by email.

An advisory that already has an issue is left alone, so its deadline does not move when
the check runs again.

## Choices

- **The clock starts when the check finds the flaw,** not when the advisory was
  published. With a weekly check, a critical flaw can be public for up to seven days
  before the clock starts. That is the cost of "weekly"; running it daily would cost
  nothing more and is an easy change if the owner wants it.
- **Only critical gets a deadline,** because that is what FR-23 says. High and lower are
  listed in the report and looked at on the next weekly check.
- **Not being able to check is a failure.** If the audit report is missing, unreadable or
  is npm's error output, the run fails. An audit that could not reach the registry is
  never read as "no advisories". Tests cover this.
- **An unknown severity is treated as critical.**
- **The workflow can open issues and nothing else.** It cannot push code or change pull
  requests.
- **It also runs when the check itself changes,** on pull requests that touch the
  workflow or its script, so a broken check cannot merge unseen. On a pull request it
  reports only and files no issues.

## First check

Run on 2026-11-22 against the pinned tree (212 packages after Wrangler was added): no
known advisories. The first run in GitHub Actions is the one on the pull request that
added this check.

## Limits

- **npm's advisory database only.** It covers npm packages. It does not cover the
  Cloudflare runtime in production, which Cloudflare patches itself, or GitHub Actions.
- **Pinned actions are not checked for updates.** Nothing yet tells the owner that a newer
  `actions/checkout` exists. Worth adding here later.
- **Nothing enforces the 72 hours.** The issue states the deadline; meeting it is on the
  owner. Until the monitoring alerts exist (task 3.1.10), the email from the failed run is
  the only prompt.
- **The scheduled path is proven only when it first fires.** GitHub pauses scheduled
  workflows in a repository with no activity for 60 days.
