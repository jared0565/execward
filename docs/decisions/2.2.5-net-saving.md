# Task 2.2.5: the net saving after verification

Built 2026-11-25. Traces to the success metric "net token saving" and FR-51. Builds on
the token meter (`1.8-token-meter.md`) and verification's model access
(`2.2.1-verification-access.md`).

## What it is

Code Mode saves tokens by keeping tool results out of the model's context.
Verification spends tokens checking the result. The net saving is the first minus the
second. A kind of run whose net saving is negative is flagged in the owner's console,
with what to consider.

## How it is counted

For every metered run, three things are added to that kind's totals
(`src/meter/net-saving.ts`):

- one run;
- the meter's estimated saving, which may be negative;
- if the reviewer was asked, one verified run and the tokens the provider says the
  review used, input plus output. A blocked run counts too: the tokens were spent.

The totals are kept in the shared counters for one 30-day period at a time, then start
again, so an old loss does not hide a present saving.

## The kind of a run

The task's done-when says "per task type". A run does not say what type of task it is,
and nothing in a call names one. So the kind is read from what the run did:

| Kind | Rule |
|---|---|
| Runs that looked for tools first (`exploratory`) | It used `search()` or `describe()` |
| Runs that called tools (`bounded_tool_heavy`) | It called tools without looking for them |
| Runs that used no tool (`no_tools`) | Neither |

This is a stand-in for the eval's task types, not the same thing. A bounded task whose
script happens to search first is counted as exploratory.

## What the owner sees

The console has a new section, "Net saving after verification", read from a new
address, `/console/saving`, behind the same sign-in as the rest. For each kind with
runs: runs, verified runs, estimated saving, verification tokens and the net. A
negative kind is marked NEGATIVE with one of two lines of advice:

- verification uses more than Code Mode saves: narrow what is verified there, or
  switch verification off for it;
- Code Mode itself loses before any verification: consider direct calls.

## Limits

- **The two sides are not the same kind of number.** The saving is an estimate from a
  rough rule of one token per four bytes. The verification tokens are the provider's
  count. The net is good for seeing sign and size, not for quoting.
- **Flagging is all it does.** Nothing narrows or switches off verification by itself,
  and there is no setting yet to switch it off for one kind of run.
- **Only the reviewer is counted.** The cross-check (task 2.2.2) makes no model call
  and uses no tokens. The daily check of the reviewer (task 2.2.4) is not a run and is
  not counted here; it is about 2,300 tokens a day.
- **Only metered runs are counted.** A run refused before it starts, or one that ends
  in a sandbox fault, writes no meter record.
- **The totals start again every 30 days**, and the old period is then swept. There is
  no history. The stats report (task 2.3.1) is where history belongs.
- **Few runs have criteria**, so few are verified. With little data a kind's sign can
  turn on one run.

## Seen on production, 2026-11-25

The owner made two reviewed runs of `return 2 + 3;` and sent a screenshot of the
console. The section showed one line: "NEGATIVE: Runs that used no tool", 2 runs, 2
verified, estimated saving -10, verification used 1,034, net -1,044, with the advice to
consider direct calls. The counters in the database read the same.

That line is right, and shows what the section is for: a script that calls no tool
saves nothing, and each review cost about 500 tokens.

Only the "used no tool" kind has been seen with runs in it.
