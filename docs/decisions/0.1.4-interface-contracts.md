# Task 0.1.4: the five interface contracts

Fixed 2026-11-22 at contract version 1.0.0 (`src/contracts/version.ts`). The contracts are
[zod](https://zod.dev) schemas with TypeScript types derived from them, so the same definition
validates data at run time and types the code. `test/contracts.test.ts` accepts a valid example
of each and refuses invalid ones.

| # | Contract | File | What it fixes |
|---|---|---|---|
| 1 | `code` tool input | `src/contracts/code-tool.ts` | `script`, `project`, and optional `intent` and `criteria`. Unknown fields are refused. |
| 2 | `code` tool output | `src/contracts/code-tool.ts` | Four statuses, each with its own shape: `completed`, `paused`, `error`, `refused`. Every one carries the run report. |
| 3 | Sandbox API | `src/contracts/sandbox-api.ts` | The five globals a script may use, the blocked constructs, and how a tool name becomes a function name. |
| 4 | Policy record | `src/contracts/policy.ts` | One record per tool, plus what the broker assumes for a tool with no record. |
| 5 | Error codes | `src/contracts/errors.ts` | Fourteen codes, each marked retryable or not, and security or not. |

## Choices made here

- **`refused` is a status** (flag 3, accepted into the PRD). It means the script never ran.
  `error` means it ran and failed.
- **Six codes beyond the eight the PRD names.** The PRD's list says "including", so it was
  open-ended. Added: `script_error`, `result_too_large`, `code_mode_off`, `sandbox_fault`,
  `circuit_open` and `injection_suspected`. Each maps to a requirement that needs a distinct
  outcome (FR-7, FR-35, FR-17, the failure-behaviour NFR, FR-27 and FR-41).
- **Security codes are never retryable**, checked by a test. `sandbox_fault` is also never
  retried, though it is not a security code: the run ends and nothing runs outside the sandbox.
- **`timeout` is retryable; `quota_exceeded` is not.** A timeout is usually a script the model
  can fix. A quota is a control, and FR-41 lists it among the failures that escalate at once.
- **Caller rules are `direct`, `script` or `both`** (FR-6). Hook-guarded tools are recorded as
  `direct` until the broker enforces the same rule (FR-13).
- **Data classes are ordered** `public`, `internal`, `confidential`, `client_personal`, so
  "above the run's class" (FR-36) is a comparison of positions.
- **Runtime validation uses zod, a production dependency.** JSON Schema validators that compile
  schemas into code need `new Function`, which Workers block. Validating tool arguments against
  each tool's own `inputSchema` (FR-34) is a separate problem, left to task 1.3.3.
