# 1.4.1, 1.4.2 and 1.4.3 The audit log

Date: 2026-11-23. Requirements: FR-8, FR-28, FR-21; flag 5. Closes task 1.3.9 (fail
closed) and the last part of 1.2.3 (the script hash is recorded). Status: **built, wired
into every run, and tested in memory and on a local D1 database.** Not deployed.

## What is recorded

Every use of the `code` tool writes to the log. There is no setting that turns it off.

| Entry | When | What it holds |
|---|---|---|
| `run_started` | Before the script runs | The script, its SHA-256, the limits, the stated intent |
| `run_finished` | Before the reply is returned | The outcome, any error, each call with its arguments and result size, the result size, the duration, the data class read, whether output was withheld |
| `run_refused` | When a run never starts | The script (redacted), its hash and the reason |

Each entry is marked as a security event or not.

## How it resists tampering

- **Hash chain.** Each entry holds the hash of the one before. Changing, removing,
  inserting or reordering an entry breaks the chain, and verification names the first
  entry that does not fit.
- **Append-only at the database.** Two triggers on the table refuse every UPDATE and
  DELETE. Tested: both are refused on the local database.
- **Both together.** Someone with enough access can remove the triggers. The chain still
  catches the edit; that is tested too.
- **A script cannot write to it.** The sandbox has no network, no bindings and no
  function that reaches the log.

## Choices

- **No record, no run; no record, no result.** If `run_started` cannot be written, the
  run is refused before the script starts. If `run_finished` cannot be written, the
  result is withheld. This is the fail-closed rule of task 1.3.9, which is now done for
  all three services: policy table, quota service and audit log.
- **Secrets are redacted before writing (FR-21),** never after. A field whose name says
  it holds a secret (`token`, `password`, `authorization` and so on) has its value
  replaced; any text shaped like a known credential has that part replaced.
- **Control characters are escaped.** A logged value cannot start a forged line or send
  commands to a terminal that prints the log.
- **The chain covers the hash of an entry's content, not the content.** Task 1.4.4 has to
  expire full text after 7 days and delete a project's logs on request. With this design
  the content can be removed and the chain still verifies. Tested ahead of that task.
- **Two writes per run, not one per call.** Calls are kept in memory during the run and
  written together at the end. Fewer writes, and the chain is not fought over by every
  call.
- **Large arguments are logged as a size.** Over 4 KB, the log records how big the
  arguments were, not their text.
- **Simultaneous writers are handled.** Each entry's number is the table's key, so two
  writers cannot take the same place; the loser reads again and retries.

## Evidence

- 27 tests in memory: the chain, eight kinds of tampering, a forged entry with correct
  hashes of its own, redaction, and what a run records in each case.
- 4 tests on a local D1 database inside the local Workers runtime: appending, four
  simultaneous writes, UPDATE and DELETE refused, and an edit made after removing the
  protection detected by the chain.

## Limits

- **Cutting entries off the end is not detected.** A chain proves that what is there is
  intact, not that nothing after it was removed. Detecting that needs the newest hash
  kept somewhere else, for example in the daily backup (task 1.4.5). Tested and stated.
- **Nobody can read the log through ExecWard yet.** "Readable only by the owner" is true
  only in the sense that there is no read route at all. The owner console (1.6.x) will
  add one behind sign-in. Anyone with access to the Cloudflare account can read the
  database directly.
- **If the last write fails after the calls were made, the calls still happened.** The
  result is withheld, and `run_started` shows the run began, but the calls are not on
  record. Today every callable tool is read-only, which bounds the harm. Tools that
  change things must log each call before it goes out; that belongs with tier 1.
- **Redaction is by name and by shape.** A password in a field called `note` is written
  as it is.
- **The script is stored in full** (it has already passed the secret scan). Its expiry is
  task 1.4.4.
- **Nothing expires yet,** and the triggers currently block the deletions 1.4.4 needs;
  that task must relax them in a controlled way.
- **Tool results are not stored,** only their size.
