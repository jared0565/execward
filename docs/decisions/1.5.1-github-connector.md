# 1.5.1 The GitHub read-only connector

Date: 2026-11-23. Requirements: architecture run step 4; NFR credentials; decision "first
wrapped tools". Status: **done. Tested against a fake GitHub, and run against
GitHub itself with a real read-only credential on 2026-11-23.**

## What it is

`src/connectors/github.ts` turns one call the broker has allowed into one request to
GitHub. It covers the fifteen read-only tools in `src/tools/github-inventory.ts`.

Three things are fixed in the code, where a script cannot change them:

| Fixed | How |
|---|---|
| The host | Every address is built from `https://api.github.com` and checked again after it is built |
| The method | Every request is a GET. The connector has no code that writes |
| The credential | Read from the secret store when a request is sent. Never in a script's inputs, a result or an error |

Redirects are not followed, so the credential cannot be carried to another host.

## Arguments

Each tool has a schema the broker checks before the connector runs: required fields,
kinds, ranges, allowed values, and no unlisted fields. The connector checks again where
an argument becomes part of an address. A repository name with a slash, a question mark,
a percent sign, a backslash or `..` is refused. A file path is split at its slashes and
each part is checked and encoded on its own.

## What is returned

For the eight tools marked sensitive: GitHub's own JSON, unchanged, with one exception: a
file's content is decoded to text. A file that is not text comes back with
`content: null` and `binary: true`.

For the seven tools that are not marked sensitive (`get_repository`, `list_branches`,
`list_commits`, `list_issues`, `list_pull_requests`, `list_releases`,
`list_workflow_runs`): a copy holding named fields only, in the places GitHub puts them.
Their policy says they return names, numbers, states and titles, and a read of one does
not stop a later outbound call. GitHub's reply holds more than that: an issue's body, a
pull request's description, release notes, whole commit messages, email addresses. None
of it is handed over. A title, and a commit message, is cut to its first line and 200
characters. A reply of the wrong kind (an object where a list is expected) is refused.
The fields are the `SHAPES` table in `src/connectors/github.ts`; a tool that is not
sensitive and has no entry there is refused. To read the full text, a script calls the
sensitive tool for the one item (`get_issue`, `get_pull_request`, `get_commit`).
(Changed 2026-11-26 after a review finding: until then these seven passed GitHub's
whole reply on.)

GitHub's error messages are passed on, cut to 200 characters, as errors a script can
catch. If the credential ever appeared in one, it is replaced before it is passed on.

## Evidence

14 tests, all against a fake `fetch`: every tool sends a GET to GitHub; thirteen attempts
to leave the host or reach another endpoint are refused; the credential is absent from
results, errors and addresses; a redirect is not followed.

## Limits

- **Run against one repository.** The real run read this project's own public
  repository with five of the fifteen tools (repository, branches, pull requests, file
  contents, issue). The others are tested against the fake only.
- **No result schemas.** Results are not checked against a declared shape, so the
  broker's result validation has nothing to check for these tools. The data-class tags
  still apply.
- **A sensitive tool's result is GitHub's full JSON,** which is large. That is fine
  inside the sandbox, where a script picks what it needs, and is what the token saving
  rests on.
- **A field GitHub adds later is not handed over** by the seven tools above until it is
  named in `SHAPES`. A script that reads a field not named there gets `undefined`, not
  an error.
- **A title is still text a person wrote.** The owner's rule lets titles through as
  metadata; one line of 200 characters is the most any of these tools passes on.
- **The definitions are ours, not GitHub's.** There is no upstream listing to compare
  against, so "the definition changed" can only mean we changed it.
- **Read-only depends on the credential too.** The connector cannot write, but the
  credential's own scope is what stops anything else that held it. Keep it read-only.
- **Rate limits are GitHub's.** The connector reports them and does not wait or retry.
