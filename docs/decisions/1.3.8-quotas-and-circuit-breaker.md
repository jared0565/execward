# 1.3.8 Quotas, spend caps and the circuit breaker

Date: 2026-11-23. Requirement: FR-27. Status: **the rules are built and every one stops a
run in tests. The counts are held in memory, which is not enough for production.** A
durable store is still owed, so the task stays in progress.

## What stops a run

| Limit | Default | When it is reached |
|---|---|---|
| Runs a minute, per project | 10 | The run is refused before the script starts |
| Runs a day, per project | 500 | Refused before it starts |
| Runs at once, per project | 2 | Refused before it starts |
| Spend a day, per project | $1 | Refused before it starts |
| Spend a month, per project | $20 | Refused before it starts |
| Upstream calls a day, per project | 10,000 | The call is refused and the run ends |
| Calls to one tool in a run | Set per tool | The call is refused and the run ends |
| Calls to one tool in a day | Set per tool | The call is refused and the run ends |
| Upstream errors in a row | 5 | The run ends with `circuit_open` |

All but the last end with `quota_exceeded`. Both codes are final: the model is not
invited to retry.

## Choices

- **A run is charged up front.** Cloudflare bills for each sandbox started, so each run
  counts as $0.002 against the spend caps when it is admitted, whatever it then does.
  Model spend is capped separately (FR-51) and is not counted here.
- **Money is counted in millionths of a dollar,** as whole numbers, so 500 runs at $0.002
  come to exactly $1 and not a rounding error either side.
- **A refused attempt still counts** against the per-minute and per-day run limits. A
  caller that keeps trying stays refused.
- **A slot for "runs at once" lapses by itself** one minute after the run's time limit,
  so a run that crashed cannot hold its slot for ever.
- **Only real upstream calls are counted.** A call refused by policy, or with arguments
  that fail the schema, never reaches the counters.
- **The circuit breaker counts failures in a row,** and a success resets it. A result the
  broker had to reject (too large, malformed) counts as a failure. A script's own
  mistakes, such as bad arguments, do not.
- **Fail closed.** If the counter store cannot answer, the run or the call is refused.
- **A script refused by the static check is not counted as a run.**

## Evidence

21 tests: each limit reached and then lifted when its window passes or a run ends, the
two spend caps, projects kept apart, a crashed run's slot, the store being down, and the
circuit breaker tripping, resetting and ignoring the script's own mistakes.

## Limits

- **The counts are in memory.** Workers run as many short-lived instances, so in
  production these counters would reset and would not be shared. Nothing enforces a daily
  limit across instances until a durable store (D1 or a Durable Object) is written behind
  the same interface. That work comes with deployment and needs a Cloudflare account to
  prove. **Until then FR-27 is not met in production.**
- **If the broker is built without a quota store it counts in memory for that run only.**
  That keeps tests simple; the production wiring must always pass the store.
- **"Per user" quotas are not built.** FR-27 says per user and project. There are no
  users until sign-in exists (tasks 1.5.x), so everything is per project.
- **The kill switch is task 1.6.5,** not this one.
- **Windows are fixed, not sliding.** Ten runs at 11:59:59 and ten more at 12:00:00 are
  both allowed. A month is a fixed 30 days.
- **"Three policy denials end the run" is moot.** The numeric limits allow three; since
  task 1.3.2 the first denial already ends the run, which is stricter.
- **Spend is an estimate from the published price,** not a reading of the bill.
