# 0.2.3 (part 2) The eval task suite

Date: 2026-11-22. Status: done.

## What it is

`src/eval/tasks/github-tasks.ts` builds 30 tasks on the fixture GitHub tools:

- 20 bounded tool-heavy tasks: the route is clear and the work is fetching and counting.
  Examples: open issues in one repository, merged pull requests, failed CI runs, the person
  with the most commits.
- 10 exploratory tasks: the model first has to find out where to look. Examples: which
  repository defines the session time-to-live, what the MAX_RETRIES constants add up to,
  who triggered the last failed run on main.

`npx tsx scripts/list-tasks.ts` prints every prompt with its expected answer. It makes no
model call.

## How answers are checked

- Every expected answer is computed from the fixture world when the suite is built, so a
  task cannot disagree with its data.
- A number check passes only if the answer names that number and no other. "14 of 48" fails.
- A name check passes only if the answer names the right item and no other candidate, so
  listing every login does not pass.
- A "most" question whose data has a tie stops the suite from building, instead of
  silently picking one winner. Two draft tasks were replaced for that reason.
- No expected answer is zero or empty, which a model could reach by doing nothing.
- The tests confirm, for every task, that the check accepts the expected answer and
  rejects an empty answer, "I could not find that" and a wrong value. Five answers are
  also re-derived through the tools themselves, not only from the raw data.

## First real pass

`npx tsx scripts/eval-suite.ts --cap 1`, 2026-11-22: every task once on each model, direct
arm, default effort, all through OpenRouter (no run needed the fallback route).

| Model | Correct | Input tokens | Output tokens | Cost |
|---|---|---|---|---|
| Claude Haiku 5.5 | 30 of 30 | 1,258,399 | 17,608 | $0.135 |
| GPT-6 Luna | 29 of 30 | 564,039 | 3,494 | $0.058 |

Total $0.19 for 60 runs. GPT-6 Luna's one miss was `open-pulls-dashboard`. Re-run three
times with answers shown, both models answered 9, the right answer, every time. So the
task and its check are sound, and the miss was an occasional slip by the model. That kind
of noise is why the baseline runs each task five times.

## What this tells us

- Cost. One pass of the suite costs about $0.19, so the direct arm of the baseline (five
  passes) is about $1. The tool-search arm should cost no more. The whole Phase 0 baseline
  is therefore about $2, below the earlier estimate of $3 to $7.
- The cheapest models already solve nearly every task. For these tasks, larger models
  would cost 20 to 80 times more for at most one more correct answer in 60.
- The other side of that: with success near 100%, the suite can show a drop but cannot
  show an improvement, and it says little about harder work. If the code-tool arm is to
  be tested on tasks that need many steps, the suite needs some harder tasks. That is a
  judgment for task 0.2.5 and 0.2.7, not decided here.
- Claude read about twice the input tokens GPT did for the same tasks (it tended to make
  one more tool call per task, and its tool overhead is larger). Token counts are compared
  within a model across arms, never between the two models.

## Limits

- One pass is one sample per task. The figures above are not yet a baseline.
- The suite runner is `scripts/eval-suite.ts`. It requires `--cap` and refuses to start a
  run once spending reaches it. When this was written only the direct arm existed. The
  runner now has four: `direct`, `tool_search`, `code` and `both` (`--arm`).
- Each result line holds the model's final answer, so a changed check can re-score old
  runs. `--show-answers` also prints the answers to the console. (At first answers were
  not saved; that changed during the baseline, task 0.2.5.)
- Raw results are written under `eval-results/`, which git ignores.
