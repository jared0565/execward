# 1.2.1 Running scripts in a Dynamic Worker

Date: 2026-11-22. Requirements: FR-4, the isolation NFR, the Sandbox API contract.
Threat-table row 4 (sandbox escape). Status: **built and tested in the local Workers
runtime. Not deployed, and not yet reachable from any route.** The proof on Cloudflare's
real runtime is task 1.2.8 and needs an account.

## What it does

`dynamicWorkerExecutor(loader)` in `src/executor/dynamic-worker.ts` is the first
implementation of the executor interface. For each run it loads the script into a new
isolate that is given:

| Setting | Value | Effect |
|---|---|---|
| Network | `globalOutbound: null` | `fetch` and raw connections fail |
| Bindings and environment | `env: {}` | Nothing to read: no keys, no storage |
| Node.js layer | switched off by two flags | No `process`, `Buffer` or `node:` modules |
| Globals | stripped before the script runs | Only the Sandbox API and the allowed language built-ins remain |
| CPU | `limits.cpuMs` | Platform limit (see Limits below) |

The script's only way out is one object the host passes in, the bridge. It forwards
`tools.*`, `search()` and `describe()` to the host, counts calls, stops at the run's call
limit, and refuses everything once the run has ended. The host keeps the wall clock.

What comes back from the isolate is treated as untrusted: each field of the report is
checked, and a report of the wrong shape is a sandbox fault. On any fault the run fails.
There is no second way of running a script.

## Three things the tests found

1. **The Node.js layer is on by default.** With the current compatibility date a Dynamic
   Worker had `process` and `Buffer`, and `import("node:fs")` succeeded. Turning it off
   needs both `no_nodejs_compat` and `no_nodejs_compat_v2`; one alone leaves `process`.
   Measured, five combinations.
2. **`fetch`, `setTimeout` and `WebSocket` are not on the global object itself** but on
   its prototypes. The first version of the stripping missed them, and so did the first
   version of the test for it, which passed. Both now walk the whole chain.
3. **The local runtime does not enforce the CPU limit.** `while (true) {}` with a 50 ms
   limit hung the local runtime for 25 seconds until it was killed. The host's own timer
   could not fire either, because locally both share one thread. So a busy loop is
   stopped only by the platform, and that can only be shown on a deployed Worker.

## Evidence

- 17 tests run the real executor inside the local Workers runtime (`workerd`), through a
  test-only Worker (`test/workers/`): tool calls, search, describe, assert, console, error
  line numbers, no extra globals, nothing readable from the prototypes, no network, no
  Node.js layer, no text-to-code by four routes, wrapper-closing scripts refused, the call
  limit, the time limit with no calls forwarded afterwards, and result and log caps.
- 16 tests on reading the report and building the modules, without the runtime.

## Limits

- **Local is not proof of isolation.** Cloudflare says the local runtime is not a hardened
  sandbox. These tests show the configuration is right and the executor behaves; they do
  not show an attacker cannot get out. That is task 1.2.8, on a deployed Worker.
- **CPU and memory limits are untested** (finding 3). Task 1.2.2.
- **A script that never yields cannot be timed out by the host.** The wall-clock limit
  works for scripts that wait (on a tool call, for example), which is the tested case.
- **Removing globals is a second layer.** The boundary is the isolate with no network and
  no bindings. A script can still reach `Function`, `Proxy` and `Reflect` at run time; the
  runtime refuses to build code from text, which is what makes `Function` harmless.
- **The adversarial suite has not been run against this executor.** Its cases pass tool
  handlers as functions, which cannot cross into the test Worker as built. Wiring the
  suite to the real executor belongs with tasks 1.2.4 and 1.2.8.
- **`setTimeout` is removed,** so a script cannot sleep or poll. Deliberate for now.
- The Workers runtime types are hand-declared in one small file, because the generated
  types clash with the Node types the rest of the repo uses.
