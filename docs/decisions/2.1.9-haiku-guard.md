# 2.1.9 The Gate 1 guard for Claude Haiku

Date: 2026-11-25. Traces to: NFR model portability; the project owner's decision at
Gate 1, 2026-11-24. Status: **built and measured on the eval. Not yet seen from a real
Claude Haiku client on production, and of little use there until a project is allowed
file contents (see Limits).**

## The problem

Claude Haiku failed one exploratory task, `rollback-command`, in every run when it had
only the `code` tool, and passed it with ordinary tool calls
(1.9.6-description-both-families.md). The owner accepted that at Gate 1 with a guard:
exploratory work stays on direct tool calls for Claude Haiku. Until now the guard was a
written rule only.

## What the owner chose

On 2026-11-24, asked how to apply it, the owner chose to give Claude Haiku both: the
`code` tool and tools it can call directly. After the first measurement the owner chose
to narrow the direct list.

## What was measured

Five runs a task, on the invented GitHub of the eval. Tokens are the median of input
plus output for Claude Haiku.

| | `rollback-command` (exploratory) | `open-issues-org` (bounded) |
|---|---|---|
| Direct calls only (baseline) | 4 of 5, 30,500 tokens | 5 of 5, 85,300 tokens |
| Code tool only | 0 of 5 | 5 of 5, about 13,000 tokens (a probe run) |
| Both, every tool listed | 3 of 5, 32,800 tokens | 5 of 5, **93,700 tokens** |
| Both, four looking-around tools, two names for a tool | 5 of 5, 13,900 tokens | 3 of 5, 21,500 tokens |
| **Both, four looking-around tools, one name (built)** | **5 of 5, 9,800 tokens** | **5 of 5, 22,200 tokens** |

What each step showed:

1. **Every tool listed loses the saving.** Claude Haiku made direct calls for bounded
   work too and spent more than with no ExecWard at all.
2. **Two names for one tool cause failures.** With the direct tool called
   `get_repository` and the script's called `github_get_repository`, both models wrote
   the direct name inside a script. That is no tool, so the run ended as a security
   failure. Listing each direct tool under the name a script uses removed this.
3. **The built form passed all 40 runs,** 20 on each model, across two exploratory and
   two bounded tasks. GPT-6 Luna also passed 20 of 20 with it, though it is not given
   it in production.

Paid runs for this task: 26 cents, in three runs of 13, 6 and 6 cents. The owner
approved about 10 cents and then about 15 more. Total against the $5 approved for the
eval: about $1.96.

## What is built

- **Which tools.** Four, for looking around a repository: `get_repository`,
  `list_branches`, `get_file_contents`, `search_code` (`LOOKING_AROUND_TOOLS` in
  `src/code-tool/direct.ts`). Counting and listing records stays with scripts.
- **For whom.** A client whose `X-ExecWard-Model` header (task 2.1.6) contains
  "haiku". Every other client is offered `code` alone, as before.
- **Which of the four are listed.** Those the owner has approved in the policy table
  and whose data the caller's provider route may receive at all. A tool above that
  level is left out, as it is from a script's search.
- **One paragraph of guidance** is added to the `code` tool's description when direct
  tools are listed: look around with direct calls; everything else, and any loop or
  total, through a script.
- **A direct call is a script.** The adapter turns it into one line,
  `return await tools.NAME(JSON.parse("..."));`, and runs it through the same service.
  Policy, data class, quotas, the static check, the release gate, the audit log, the
  retry limit and the switches all apply, because nothing else runs it. The reply
  comes back inside the untrusted-output block.

## Why the model's name is safe to act on

The header is the client's own word and is not checked. Claiming to be Claude Haiku
gains a caller nothing a script could not already do: the same tools, under the same
checks, with the same result. It changes which tools are listed. It does not sign
anyone in, raise the provider route or widen what a project may read.

## Evidence

- `test/direct-tools.test.ts`: the one-line script calls the named tool with exactly
  the arguments given; hostile text in arguments stays data; a key named `__proto__`
  stays an ordinary key; bad names and non-object arguments are refused before a
  script exists; the static check accepts the script; which tools are listed and why;
  the eval arm.
- `test/mcp-adapter.test.ts`: the tools are listed after `code`; a direct call reaches
  the service as a script; a call with no project runs nothing; it counts against the
  retry limit; a direct tool cannot take the `code` tool's name.
- `test/mcp-production.test.ts`: listed for a Haiku header, not for another model or
  none; nothing listed when the policy table cannot be read or is empty; the header
  does not sign anyone in.
- `test/deployed/mcp.deployed.ts`, on Cloudflare: the list for a Haiku header; a direct
  call runs in the real sandbox and returns inside the untrusted block; wrong arguments
  are refused by the broker's check; a client that did not ask gets no direct call.
- `eval-results/both-1.jsonl`, `both-2.jsonl`, `both-3.jsonl`: the three measurements.

## Limits

- **On the owner's production today it lists two tools, and neither reads a file.**
  The sign-in does not show how a client reaches its model provider, so the route is
  "unknown" and its ceiling is internal data. `get_file_contents` and `search_code`
  return confidential data and are left out. A Haiku client there gets
  `get_repository` and `list_branches` directly, which is not enough to explore a
  repository. The guard becomes useful when a route approved for confidential data can
  be established for a client.
- **A listed tool can still be above a project's level.** Listing goes by the route's
  ceiling; a project may be lower. A direct call in such a project is refused as a
  script's would be, and pauses the project as a security exception.
- **Measured on four tasks, five runs each.** That shows the task now passes and the
  saving is mostly kept on two bounded tasks. It does not show there is no harm on the
  other 26 tasks. The full suite was not rerun with this arm.
- **The bounded task costs more than with the code tool alone** (about 22,000 tokens
  against about 13,000), because Claude Haiku still looks at each repository with a
  direct call first. It is about a quarter of the cost of direct calls only.
- **In the eval a direct call goes straight to the invented GitHub.** That it goes
  through the service on the live path is shown by the tests, not by the eval.
- **Not seen from a real Claude Haiku client.** Added to the live checks.
- **The tool list now depends on the model header.** It is still fixed for a given
  client configuration and still does not change during a session (task 2.1.3).
