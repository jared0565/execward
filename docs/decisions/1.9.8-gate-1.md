## Limits the owner passed it with

1. **"Every P0 security requirement in place" was judged by every P0 task being Done.**
   The requirements document was not re-read line by line against the code for this
   gate. The owner was offered that audit and chose to pass without it.
2. **Five tasks are proven in tests and not yet seen on the live system** (1.3.8, 1.6.3,
   1.6.6, 1.6.8, 1.6.9), because production serves no runs until Phase 2. Task 2.1.8
   checks each one live.
3. **One eval task fails every run on Claude Haiku with the code tool** and passes with
   direct calls, which the success target as written does not allow. The owner
   accepted it with a guard: exploratory tasks stay on direct calls for that model. The
   guard is a written rule; task 2.1.9 puts it in code.
4. **The fixes that followed the sandbox review were not reviewed a second time** by
   another model family. Each has a test.
5. **Added latency is at the edge of the budget for scripts with 50 tool calls.**
6. **Eight attacks in the suite cannot be tried,** because the parts they attack do not
   exist yet. Each is tied to the task that builds the part.
7. **The eval used one small model from each family,** on invented data.
8. **No paid human review of the sandbox has been done.** That is task G.10, and it
   comes before any real client data (task G.7).
