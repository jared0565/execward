# 0.2.5 (part 1) The tool-search arm

Date: 2026-11-22. Status: arm built and piloted. The baseline was run
later the same day: see docs/research/0.2.5-baseline-report.md, which supersedes the pilot
figures here.

## What the arm is

In the direct arm the model is offered all 15 GitHub tools on every turn. In the
tool-search arm (`src/eval/arms/tool-search.ts`) it is offered two tools and nothing else:

- `search_tools(query)` returns the matching tools, at most five, each with its name,
  description and input schema;
- `call_tool(name, arguments)` calls a tool that a search has returned. A tool that has
  not been found is refused.

So tool definitions enter the conversation only when asked for. Comparing the two arms
shows what deferring definitions saves by itself, before any code tool exists. That is the
question behind the PRD risk "tool search alone captures most of the saving".

This design was Claude's choice and was not discussed with the owner beforehand.

## Why two fixed tools, and what was tried first

The first design added each found tool to the list of offered tools, so the model could
call it natively on the next turn. A pilot on 2026-11-22 showed that Claude rejects this:
6 of 30 Claude Haiku 5.5 runs failed with

> 400 ... Invalid `signature` in `thinking` block. The block is bound to a different
> conversation. ... The `tools` list differs from the one this block was created with.

Claude's thinking blocks are bound to the exact tool list they were written under, so a
conversation whose tool list changes cannot be replayed once the model has thought.
GPT-6 Luna accepted the changing list (30 of 30 correct).

With two fixed tools the list never changes, and the same arm runs unchanged on both
model families and on every route.

Alternatives not taken:

| Alternative | Why not |
|---|---|
| Each provider's own tool-search feature | Different on each provider and not known to pass through OpenRouter, so the two families would be measured differently. It is what Claude Code itself uses, so it may be worth a third arm later. Not checked against the providers' current documentation. |
| Ask Claude to drop the mismatched thinking blocks (a beta setting) | The model would lose its own reasoning mid-task, so the arm would measure a handicapped model. |

## The search itself

Plain keyword matching on each tool's name and description: a word found in the name
counts three, in the description one, and a plural "s" is ignored. A test confirms that
each of the 15 tools is found by plain words for what it does. With only 15 tools a
smarter search would change little.

## Pilot results

One pass of the 30 tasks per model and arm, default effort, 2026-11-22. All tool-search
runs used the providers' own APIs (see the OpenRouter note in 0.2.4).

| Model | Arm | Correct | Input tokens | Output tokens | Cost | Mean turns |
|---|---|---|---|---|---|---|
| Claude Haiku 5.5 | direct | 30 of 30 | 1,258,399 | 17,608 | $0.135 | not recorded |
| Claude Haiku 5.5 | tool search | 29 of 30 | 1,057,352 | 19,176 | $0.115 | 3.2 |
| GPT-6 Luna | direct | 29 of 30 | 564,039 | 3,494 | $0.058 | not recorded |
| GPT-6 Luna | tool search | 30 of 30 | 504,080 | 5,652 | $0.053 | 3.4 |

Read with care: this is one run per task, so the differences in correct answers (one task
either way) are noise, and the direct-arm pass went through OpenRouter while the
tool-search pass went direct.

What it suggests, to be confirmed by the baseline:

- Tool search cut input tokens by about 16% on Claude and 11% on GPT. The saving is
  modest because, with 15 tools, the definitions are a small share of the tokens: most
  tokens are tool results (pages of issues, commits, runs).
- Success did not visibly change.
- Claude made 13 tool calls that returned an error in this arm (none in the first design
  and none for GPT). The cause was not examined; the baseline will count them.

If the baseline confirms this, the answer to task 0.2.7 leans the way the PRD expected:
for these tasks the cost is in tool results, which tool search does not touch and a code
tool can.

## Running it

`npx tsx scripts/eval-suite.ts --arm direct --arm tool_search --runs 5 --cap <dollars>`.
`--direct-route` skips OpenRouter. The plan line shows the number of runs before any call.

One pass of both arms on both models costs about $0.36, so the baseline (five passes, 600
runs) should cost about $1.80.

## Spend so far

About $1.06 in total on 2026-11-22, of which $0.30 was the two tool-search pilots.
