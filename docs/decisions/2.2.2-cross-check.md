# Task 2.2.2: the cross-check of critical figures

Decided and built 2026-11-25. Requirement: FR-43. Critical figures are money amounts
and any total that goes to a client (the owner's answer of 2026-11-22).

## The owner's decision, 2026-11-25

A figure becomes critical when the script declares it. ExecWard then works it out
again itself, with no model call and at no cost. A second model as the other computer
(the PRD's alternative) is not built; it would need the verification key, a model
choice and a paid run.

## How it works

A script calls:

```js
const total = critical("invoice total", sum, { op: "sum", rows: amounts });
```

- `rows` is the list of numbers the figure was worked out from. `op` is one of `sum`,
  `count`, `min`, `max`, `average`. The call returns the value, so it can be used in
  place of the bare figure.
- **In the sandbox the figure is only written down.** The rows are copied at that
  moment. Nothing inside the sandbox is trusted to do the checking.
- **After the run, the host works each figure out again** from those rows, with its own
  arithmetic (`src/verify/cross-check.ts`), and compares. What came out of the sandbox
  is treated as untrusted: every part is checked first.
- **Agreement passes by itself.** The run report says how many figures were checked:
  `crossChecks: { agreed, disagreed }` (contract 1.7.0).
- **Disagreement holds the result.** The reply is `paused`, with the queue item's ID
  and one fixed line telling the model the result is waiting for the owner. Nothing the
  script wrote goes back: not the result, not its logs. The owner's queue gets a
  "cross-check disagreement" item with every figure and both values, the PRD's four
  options, and "Use the deterministic result" recommended. It closes by itself after 24
  hours.
- **A declaration that cannot be checked is an error, never an agreement.** The model
  gets `script_error` saying which figure and why, and can fix its script.
- **If the queue cannot take the item, the result is still withheld**, as an error.
- **Both values of every figure go to the audit log**, whether they agreed or not.

## Choices made, and why

- **Two sums are allowed to differ in their last binary places.** Adding the same
  numbers in a different order can change the sixteenth digit. The allowance is one
  part in a million million, and never less than a thousand-millionth: below a penny
  on any amount under a thousand million. Tested: a penny's difference at 999,999,999
  is a disagreement; 10,000 amounts added forwards and backwards agree.
- **The host's sum does not lose small numbers beside large ones** (Neumaier's method),
  so its answer does not depend on the order of the rows.
- **Limits per run:** 20 figures, 20,000 rows in all, names of 100 characters at most.
- **When the run read data above the project's class**, the counts are left out of the
  report with everything else: a script chooses how many figures it declares, so the
  number could carry what it read. The check still runs, and a disagreement still goes
  to the owner.
- **The line in the tool's description is short**, because the description has a limit
  of 1,500 characters that protects the token saving, and it now stands at 1,493. The
  line shows the form of the call and no more. What the description leaves out, the
  sandbox's own error messages say: which calculations exist, and what `rows` must be.

## What it catches, and what it does not

It catches a wrong calculation over the right numbers: text joined to text in place of
numbers added, a loop that stops one short, a rounding step in the wrong place.

It does not catch:

- **The wrong numbers.** If the script read half the pages and hands over half the
  rows, both sides agree on the same wrong total. `assert()` on page counts is the tool
  for that (FR-40).
- **A figure the script did not declare.** Nothing marks a figure as critical except
  the script. No tool in the policy table is marked as returning money, and none of
  today's 15 does.
- **A declared value that differs from the one returned.** The check compares the value
  given to `critical()` with the rows. It does not look for that value in the result.
- **A script that sets out to deceive.** It can hand over rows that match a false
  figure. This check is for mistakes, not attacks.

## Not done, or not seen

- **Choosing an option in the queue records the choice and nothing more.** No run is
  kept open to be resumed: holding and resuming a run arrives with approvals in Phase 3
  (task 3.1.6). "Use the deterministic result" therefore shows the owner the server's
  figure in the console; it does not send it back to the model. To get a result, the
  task is run again.
- **Whether models use `critical()` unprompted, and correctly, is not measured.** That
  needs a paid eval run. The eval tasks have no money figures today.
- **The longer description was not re-measured for its effect on token saving or
  success.** It grew by 78 characters.
- **Not seen on production.** The sandbox part is tested in the local Workers runtime;
  the hold and the queue item are tested with in-memory stores. A live check is owed:
  a script with a wrong declared total, run from Claude Code against production, should
  come back `paused` and appear in the console with both figures. It is listed in
  `2.1.8-live-checks.md`.
- **The second model** as the other computer, for figures code cannot work out again.
