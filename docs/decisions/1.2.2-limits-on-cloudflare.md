# 1.2.2 and 1.2.8: limits and escape cases on Cloudflare itself

Date: 2026-11-23. Requirements: FR-4, FR-31, FR-33. Status: **1.2.2 done. 1.2.8 passes by
hand; not yet in CI.**

## What was built

A second Worker, `execward-test`, deployed to the owner's Cloudflare account. It is the
local test Worker behind one gate: every request must carry a long random test secret.
The owner chose this over a Worker with no address. It holds no other credential, and
its database holds only what tests write. The secret and the address are in files in the
owner's home folder, not in the repository.

`npm run deploy:test-worker` deploys it. `npm run test:deployed` runs 16 tests against it.

## What the tests show, on the real platform

| Case | Result |
|---|---|
| A script that spins the processor | Ended by Cloudflare. Reported as `timeout` |
| A script that takes too much memory | Ended by Cloudflare. Reported as `quota_exceeded` |
| A script that waits past its time limit | Ended by the host. `timeout`. Nothing is forwarded afterwards |
| A script over its call limit | `quota_exceeded`, even when it swallows the errors |
| The next script after one was ended | Runs normally |
| Globals, network, environment, Node.js layer | None reachable |
| Turning text into code, four routes | All refused |
| Closing the wrapper, import statements | Not loaded |
| Twenty counts, ten slot requests, five switch changes at once, on a real D1 database | Exact, as locally |

Running a script in the Worker Loader at all also shows the account is on Workers Paid.

## What was found and fixed

**CPU and memory endings were reported as `sandbox_fault`.** That is a security code, so
a script that merely ran too long would have closed its task and paused the project. The
executor now recognises the two messages Cloudflare gives and reports `timeout` and
`quota_exceeded`. A script cannot fake them: an error a script throws is caught inside
the sandbox and comes back another way. Anything else is still a fault.

## Limits

- **A busy loop is stopped by the CPU limit, not the wall-clock limit.** A script that
  spins never yields, so the host's timer does not fire until Cloudflare ends the
  isolate. With a 5,000 ms CPU limit and a 500 ms wall-clock limit, the run ended after
  about 7 seconds. In production the CPU limit is 1,000 ms, so that is the bound.
- **The CPU limit is coarse.** A 50 ms limit took about 2 seconds to end the run.
- **Not in CI.** The tests need the address and the secret. Putting those in the
  repository's secrets is the owner's decision.
- **The mapping of the two messages is tested only on the deployed Worker.** The local
  runtime does not enforce these limits, so `npm test` cannot reach that code. If
  Cloudflare rewords a message, the run is reported as a fault again: safe, but only
  the deployed tests would notice.
- **A public address exists.** Without the secret it answers 401 and does nothing else.
