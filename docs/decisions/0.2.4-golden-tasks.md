# 0.2.4 The first golden tasks

Date: 2026-11-22. Status: done.

## What they are

Golden tasks are known-answer tasks meant to run daily on every model in use (FR-45, task
2.2.4). A failure removes that model as a default and tells the owner. So a golden task
must be passed reliably by a healthy model: a task that a good model misses now and then
would raise false alarms.

`src/eval/tasks/golden.ts` names nine tasks from the eval suite, each exercising a
different tool:

| Task | Tool it leans on |
|---|---|
| `dashboard-version` | `get_file_contents` |
| `latest-release-date-dashboard` | `list_releases` |
| `refund-window` | `search_code` |
| `retries-sum` | `search_code` across repositories, then arithmetic |
| `failed-pr-runs-dashboard` | `list_workflow_runs` with filters |
| `public-repo` | `get_repository` |
| `last-merged-pull-author` | `list_pull_requests`, then comparing dates |
| `closed-bugs-billing` | `list_issues` with filters, pull requests excluded |
| `pull-additions-billing` | `get_pull_request` or `list_pull_request_files` |

Five are exploratory and four are bounded tool-heavy. Each has a known answer computed
from the fixture and an automatic check, as the task's done-when asks.

`npx tsx scripts/eval-suite.ts --golden --cap <dollars>` runs them.

## Evidence for the choice

They were picked as the cheapest tasks that together cover the tools, then checked against
every real run made so far (direct arm, default effort):

- All nine passed every time: 75 of 75 runs, 4 or 5 runs per task per model, on both
  Claude Haiku 5.5 and GPT-6 Luna.
- Mean cost $0.0008 per run, so one daily pass on both models costs about $0.014, roughly
  $0.43 a month.
- The two tasks that a model has missed once (`open-pulls-dashboard` on GPT-6 Luna,
  `open-security-org` on Claude Haiku 5.5) are not in the golden set.

Four or five clean runs per task is thin proof of "always passes". The false-alarm rate
will only be known once they run daily. Task 2.2.4 should require two failures in a row,
or a re-run on failure, before it removes a model as a default. That is a recommendation
for 2.2.4, not built here.

## A mistake, and what it cost

The reliability run was meant to be the nine golden tasks five times (90 runs). My edit
adding the `--golden` switch had not applied, and I started the run without checking. The
runner ran the whole 30-task suite instead, until the $0.50 cap stopped it at $0.53 with
99 runs not started. The cap worked as designed; the overshoot of $0.03 is the four runs
already in flight.

What changed because of it:

- The runner now prints its plan before any call ("plan: 90 runs = 9 tasks x 2 models x 5
  runs, cap $1"), and `--dry-run` prints the plan and stops.
- The key check now comes after the plan, so a dry run needs no keys.

The run was not wasted: it is 201 more real runs of the direct arm. Across every run so
far, Claude Haiku 5.5 is correct on 130 of 131 and GPT-6 Luna on 129 of 130. These are
pilot runs, not the baseline: the baseline (0.2.5) will be run again in full, both arms.

## OpenRouter key limit reached

During that run OpenRouter began refusing calls with "403 Key limit exceeded (total
limit) ... $10.00 of $10.00 used; does not reset". The eval spent about $0.68 of that; the
rest of the $10 was used before this work began. Fifteen runs then fell back to the
provider's own API and all fifteen succeeded, so the fallback is proven on a real failure.

Until the owner raises that key's limit, every run pays one failed OpenRouter attempt
(free) and then uses the direct route.

## Spend so far

About $0.76 in total on 2026-11-22: $0.68 through OpenRouter and $0.08 direct.
