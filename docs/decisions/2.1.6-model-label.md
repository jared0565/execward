# 2.1.6 The model's name, passed in by each CLI

Date: 2026-11-24. Traces to: PRD "Token metering: limits". Status: **done as far as
passing the name in. Not yet seen from a real CLI on production; the report that
groups by it is task 2.3.1.**

## The problem

MCP requests carry no field for the model. The server cannot tell which model wrote a
script. The PRD's answer: each CLI's own configuration passes the name in.

## How

A CLI sets one header on the ExecWard server in its MCP configuration:

| CLI | Setting |
|---|---|
| Claude Code | `claude mcp add --transport http execward https://mcp.execward.com/mcp --header "X-ExecWard-Model: <model>"` |
| Codex | In `config.toml`, on the server: `http_headers = { "X-ExecWard-Model" = "<model>" }` |

`X-ExecWard-Client` may name the client. Without it, the name is the first word of the
CLI's `User-Agent`, for example `claude-code`.

`callerLabels` in `src/mcp/production.ts` reads them. Each run's metering line then
carries `labels: { model, client }`, which is what a report groups by.

## These are the client's own words

They are not checked. They do not sign anyone in and do not change what a caller may
read: the provider route stays "unknown", the most cautious setting,
whatever a header claims. A value that is not a plain short name (letters, digits and
`. _ : / -`, at most 80 characters) is dropped.

## Evidence

`test/mcp-production.test.ts`: names from both CLIs' styles are read; hostile and
malformed values are dropped; a label reaches a metering record; a claimed model or
client does not sign anyone in or raise the provider route.

## Limits

- **Not seen from a real CLI.** In particular, that Cloudflare Access passes a custom
  header through to the Worker for a request carrying a CLI's token is expected, not
  observed. Added to task 2.1.8.
- **The name is fixed in configuration.** A user who changes model inside a session
  (Claude Code `/model`) is still reported under the configured name.
- **No report groups by it yet.** The labels are on each metering line in Cloudflare's
  logs. The stats report is task 2.3.1.
- **A client can say anything.** That is acceptable for a label on the owner's own
  reports. It would not be for a control, and it is used for none.

## Added 2026-11-25: one more use

Since task 2.1.9 the model's name also decides whether a few tools are listed for
direct calls beside `code`: they are, when the name contains "haiku". This is still
not a control. A direct call is run as a script under every check a script meets, so
the name changes how a client may ask, not what it may get. See 2.1.9-haiku-guard.md.
