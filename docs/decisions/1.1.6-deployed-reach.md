# 1.1.6 What the deployed core can reach

Date: 2026-11-23. Requirement: FR-24. Status: **bindings, environment values and secrets
are checked against the live Worker. The open network is not, and cannot be by this
means.**

## What was built

`npm run check:deployed` asks Cloudflare which version of the production Worker is live,
which bindings that version has and which secrets the Worker holds, and compares them
with the allowlist in `src/worker/bindings.ts`. It reads only. It exits 1 on any
difference.

This closes the gap the configuration check left open: that check reads the file in the
repository, and cannot see a binding or a secret added in the Cloudflare dashboard.

| Reported as a problem | Why |
|---|---|
| Any binding not on the allowlist, of any kind | Includes environment values and secrets bound as values: the platform lists them as bindings |
| An allowed name of another kind, or pointed at another database or bucket | The name alone proves nothing |
| An allowed binding that is missing | The Worker is not the one described |
| Any secret | None is allowed yet |
| A compatibility date other than the pinned one | Runtime behaviour is pinned (FR-23) |

## Evidence

- 8 tests on the comparison, using what Cloudflare actually reported.
- Run against production on 2026-11-23: the live version has `BACKUPS` (R2), `DB` (D1)
  and `LOADER` (Worker Loader), no secrets, and nothing else.

## Limits

- **The open network is not covered.** A Worker can always make outbound requests; no
  binding is needed, so no list of bindings can show it cannot. What holds today is
  weaker: the production Worker's code makes no outbound request, and a script in the
  sandbox has no network at all (tested on Cloudflare, task 1.2.8). The GitHub connector
  will need outbound requests when it is wired in, to one host. Restricting the core's
  own outbound requests to named hosts is not built.
- **Run by hand.** It needs a signed-in Wrangler, so CI cannot run it. Someone has to.
- **A moment in time.** It says what is live now. A binding added and removed between
  two runs is not seen. Cloudflare's own audit log is the record of that.
- **It trusts Cloudflare's report** of the bindings.
