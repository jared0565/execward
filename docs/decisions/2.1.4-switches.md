# 2.1.4 Switches per client, project and tool

Date: 2026-11-24. Requirement: FR-18; PRD "Feature switch table"; PRD risk
"Mid-session toggling". Status: **done,** with one client-side check not yet observed
(see Limits).

## The four levels, and where each is set

| Level | Where it is set | Built in |
|---|---|---|
| Global | The Code Mode switch and the kill switch, in the owner console | Tasks 1.6.3, 1.6.4 |
| Project | Pause and resume, in the owner console. A security exception also pauses | Task 1.6.5 |
| Tool | Block and unblock, in the owner console. Each tool's caller rule in the policy table | Tasks 1.6.5, 1.3.x |
| Client | The CLI's own control: Claude Code `/mcp disable <name>`, Codex `enabled = false` | Nothing to build: a disabled server is not called |

## Three decisions by the project owner, 2026-11-24

The PRD's wording did not match what was built in three places. The owner chose:

1. **Any "off" stops the call.** The PRD says "the narrowest setting wins: tool, then
   project, then client". Read literally, a narrow "on" could re-open something wider
   that the owner closed. Instead: a call runs only if the global switch, the project
   and the tool are all on, and the client has not disabled the server. This is
   stricter than the PRD's wording, on purpose.
2. **With Code Mode off, the tool stays listed and calls are refused.** The PRD says
   switching off "removes the `code` tool". Over MCP the list is fixed (task 2.1.3), so
   that nothing can change under a model and no client cache is disturbed. A call made
   while off gets a plain refusal, `code_mode_off`.
3. **A client is told about a change on its first call after it.** MCP has no
   sessions, so "mid-session" is read as "since this caller's last call in this
   project".

## The change notice

`src/mcp/switch-notice.ts`. The settings that bear on a caller in a project are
remembered: Code Mode, the kill switch, whether the project is paused, and which tools
are blocked. At the next call, if they differ, the reply carries one plain line per
change, for example "This project was paused since your last call in this project.
Calls are refused until the owner resumes it." It is said once, whether the call then
runs or is refused.

The lines travel in a new optional field of every reply, `notices` (contract 1.6.0).

## Evidence

- `test/switch-notice.test.ts`, 17 tests: each kind of change and its reverse, several
  at once, the cap on lines, a hostile tool name shown as quoted data, callers and
  projects kept apart, a change undone before the caller returns, and a reply that
  still matches the contract.
- `test/deployed/mcp.deployed.ts`, on Cloudflare with the database: a project is
  paused while Code Mode is on and the call is refused with the notice; the notice is
  not repeated; with Code Mode off the call is refused, the tool is still listed, and
  both changes are named; switched back on, the call runs and says so.
- Codex 0.169.0, asked with a throwaway setting and an invented address, lists a server
  set `enabled = false` as disabled and keeps its configuration.

## Limits

- **Claude Code's `/mcp disable` was not observed here.** It is an interactive command
  and trying it would change the owner's own settings. It is taken from Claude Code's
  documentation. Seeing it once is added to task 2.1.8.
- **Codex was seen to list the server as disabled.** That it then sends nothing in a
  session was not observed.
- **A notice says what changed, not when or by whom.** The switch state does not carry
  times. The audit log does, for the owner.
- **A notice is a courtesy, not a control.** If the remembered settings cannot be read
  or written, the call goes ahead without one. The switches themselves are enforced
  whatever happens to the notice.
- **A notice sits inside the block marked as untrusted output,** with the rest of the
  reply. A model is told to weigh that block as information, which is the right
  reading of a notice too.
- **Switching off during a run** does not end the script early. The switches are read
  when a run starts and again before each tool call (every 0.25 s at most), so a run
  in flight is stopped at its next tool call. In Phase 2 no tool has side effects.
- **Claude Code and Codex share one memory per project,** because both sign in as the
  owner. Whichever calls first after a change gets the notice.
