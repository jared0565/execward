# Task 0.1.5: GitHub read-only inventory

Drafted 2026-11-22. The inventory is `src/tools/github-inventory.ts`: 15 read-only GitHub
actions, each with a draft policy record. `test/github-inventory.test.ts` checks every record
is complete and read-only.

## The 15 actions

| Tool | Reads | Data class | Sensitive |
|---|---|---|---|
| `get_repository` | Repository details | internal | no |
| `list_branches` | Branch names and head commits | internal | no |
| `list_commits` | Commit history | internal | no |
| `get_commit` | One commit with its diff | confidential | yes |
| `get_file_contents` | A file or directory listing | confidential | yes |
| `search_code` | Code search results | confidential | yes |
| `list_issues` | Issue titles, states, labels | internal | no |
| `get_issue` | One issue with its body | confidential | yes |
| `list_issue_comments` | Comments on an issue or pull request | confidential | yes |
| `search_issues` | Issue and pull request search | confidential | yes |
| `list_pull_requests` | Pull request titles, states, branches | internal | no |
| `get_pull_request` | One pull request with its description | confidential | yes |
| `list_pull_request_files` | Files a pull request changes, with patches | confidential | yes |
| `list_releases` | Releases | internal | no |
| `list_workflow_runs` | CI runs and their results | internal | no |

All 15 are tier 0, callable directly or from a script, and not outbound.

## How the classes were chosen

- **Metadata is internal.** Names, numbers, states and titles from a private repository are not
  public, but they are not client material either.
- **Code and free text are confidential and sensitive.** A private repository can hold client
  code, and issue or pull request text is written by people and can carry anything. Marking
  these sensitive means a run that used one cannot then call an outbound tool (FR-29).
- **Nothing is public.** The class is set by the worst case the tool can return, and the same
  tool reads private repositories as well as public ones.
- **Nothing is client personal data.** No tool here targets personal data. If a repository
  holds it, the project's own data class covers that (FR-38).

## Limits of this draft

- **The selection is a proposal.** The PRD says "only you know the inventory". These 15 cover
  reading code, issues, pull requests, releases and CI. Actions left out on purpose: anything
  that lists users, organisation members or secrets, and all GraphQL.
- **Search queries leave the sandbox.** `search_code` and `search_issues` send a query string
  to GitHub. That goes to the same provider the data came from, so they are not marked
  outbound, but the query is an argument the broker validates and can flag as unusually large.
- **No definition hash yet.** It is added when the connector's tool definitions are written and
  pinned (tasks 1.5.1 and 1.5.4).
- **Endpoints are from GitHub's REST API as I know it**, not re-checked against the current
  reference. Task 1.5.1 verifies each one when it builds the connector.
