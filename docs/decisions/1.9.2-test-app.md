# 1.9.2 The test app, and 1.7.2 the summary check

Date: 2026-11-23. Requirements: FR-9, FR-16, FR-39. Status: **done. Built, tested
against stand-in models, and run with a real Claude model and a real GPT model on
2026-11-23** (see "The run with real models" below). 1.7.2 is done.

## The test app (`src/app/agent.ts`)

A minimal agent loop: one call handles one user request.

- **Code Mode on:** the model is offered exactly one tool, `code`. No wrapped tool is
  named anywhere in what it is sent. A direct call to a wrapped tool is refused.
- **Code Mode off:** the `code` tool is gone and the same wrapped tools are offered for
  direct calls. A call to `code` is refused with `code_mode_off`.
- **The switch is read every turn,** so a change takes effect at the next model turn.

What the app does that the model cannot:

- **It sets the project and the provider route.** The model is not offered either as an
  argument, and anything it sends for them is dropped.
- **It holds the retry count** for the request (task 1.7.3): one count per request.
- **It hands results to the model as untrusted data,** wrapped as task 1.3.6 defined.
- **It checks the model's final summary** (below).

It reuses the model adapters and types the eval harness already has, so the same code
reaches Anthropic, OpenAI and OpenRouter.

## The summary check (`src/app/reconcile.ts`, task 1.7.2)

Every figure in the model's final answer must be traceable to something the server
knows: the user's request, a value returned to the model during the task, or a count in
a run report. A figure found in none of those is flagged, and the flag travels with the
answer.

**A flag means "not traceable", not "wrong".** A model that adds two returned numbers in
its head produces a figure this cannot trace. The way to get a traceable figure is to
compute it in the script.

## A finding for the owner

**A typo can close a task.** The static check (task 1.2.3) refuses a script that uses a
name it does not know, and reports it as `static_check_failed`, a security code. Since
task 1.7.3, a security code closes the task with no retry. So a model that misspells a
variable, or reaches for a harmless built-in that is not on the list, loses the whole
request and it is escalated.

That is the rule as written, and it is the cautious reading: the same check stops
`fetch` and `process`. But it will make real models fail tasks they could have fixed in
one retry. Splitting the check's refusals into "tried something forbidden" (no retry)
and "used an unknown name" (retry) is a small change, and it is a security trade-off, so
it is the owner's call. Nothing was changed here.

**Settled 2026-11-23.** The owner chose the split. See the last section of
docs/decisions/1.2.3-static-check.md.

## Limits

- **The real run was six tasks.** Three simple questions, two models, one repository.
  It shows the path works end to end. It says nothing about success rates; that is the
  eval, task 1.9.5.
- **Direct calls do not go through the broker.** With Code Mode off the app calls
  whatever backend it was given. Policy, quotas, the audit log and the data-class cap
  apply only to the `code` tool. The PRD's "hook-guarded" direct path is not built.
- **Turning Code Mode off mid-run does not stop a script already running.** That is
  task 1.6.4.
- **The summary check reads figures only.** A summary that says "no issues are open"
  when three are is not caught. Claims in words are the reviewer's job (Phase 2).
- **Small numbers pass easily.** If any tool returned a 3 anywhere, a wrong "3" in the
  summary is traceable and passes.
- **The app is a library function, not a served app.** Nothing exposes it over HTTP.

## The run with real models

2026-11-23, with the owner's go-ahead and a cap of $1. `scripts/app-real-run.ts --direct`.

Everything in the path was real: Claude Haiku 5.5 and GPT-6 Luna through each provider's
own API; the `code` tool on the deployed test Worker (static check, sandbox, broker,
pinned definitions, policy); the GitHub connector reading this project's public
repository with the owner's read-only credential. Three questions each: the default
branch, a pinned version in `package.json`, and how many of the last ten pull requests
were merged.

| | First run | After the fixes |
|---|---|---|
| Correct | 4 of 6 | 6 of 6 |
| Runs that ended in an error | 7 | 0 |
| Tasks closed and escalated | 2 | 0 |
| Cost | $0.007 | $0.012 |

Raw results: `docs/research/data/1.9.2-real-run.jsonl` and `1.9.2-real-run-2.jsonl`.

Neither model was told a tool name. Both found the tools with `search`, read their types
with `describe`, and wrote scripts that worked.

### What the first run found

1. **A cut result was withheld as a sandbox fault.** Both models first returned the whole
   list of pull requests, about 35,000 bytes. The executor cut it to the 32,768-byte
   limit, as designed. But the cut text is then sent as a JSON string, where every quote
   is escaped, and it grew back over the limit. The release gate, seeing a size that
   "could not happen", withheld the reply as `sandbox_fault`: a security code, so the
   task was closed and escalated. Any cut result made of real JSON did this; the earlier
   test used plain text, which has no quotes. Fixed in `truncationNotice`: the text is
   cut to what fits once sent. Seven tests, four of which fail without the fix.
2. **Claude passed `search` something other than a string,** on every task, and lost a
   turn to it. The tool description now shows that `search` and `describe` each take one
   string. In the second run it did not happen.

### What the second run shows about cost

The pull-request question cost three times the others (28,000 to 39,000 input tokens
against 7,000 to 12,000). Both models still returned the whole list first, received the
cut 32,000-byte reply with its notice, and only then wrote a script that returned a
count. **A cut reply is a correct outcome and an expensive one.** The description already
says to return a small value. Whether models can be brought to do that first time is a
question for the eval.

### Limits of this run

- The OpenRouter key had reached its own lifetime limit, so the run used each provider's
  own API instead. The baseline (task 0.2.5) used OpenRouter. The models are the same.
- The provider route was recorded as "unknown". The test Worker's route does not apply
  the rule that matches a project's data class to a provider route; the data read was
  one public repository.
- Simple questions take four to seven model turns, most of them spent finding the tool.
