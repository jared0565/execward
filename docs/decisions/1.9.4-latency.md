# 1.9.4 The latency the core adds

Date: 2026-11-23. Requirement: NFR performance. Budget (task 0.2.6): 10% of run time or
0.5 seconds per run, whichever is larger. Status: **measured for the sandbox and the
checks. The database round trips are not in the measured path yet.**

## Result

Measured on the deployed test Worker with `npm run measure:latency`: 40 samples of each
case, one at a time, timed from the owner's machine, after two warm-up requests.

| Case | Median | 95th percentile | Added over baseline (median) |
|---|---|---|---|
| Baseline: a request refused at the test Worker's gate | 28 ms | 96 ms | — |
| Script with no tool call | 35 ms | 72 ms | 7 ms |
| Script with 1 tool call | 31 ms | 44 ms | 4 ms |
| Script with 10 tool calls | 34 ms | 65 ms | 7 ms |
| Script with 50 tool calls | 45 ms | 70 ms | 17 ms |
| Script refused by the static check | 18 ms | 30 ms | below the noise |

**Against the budget: the static check, the sandbox and the contract checks add between
4 and 17 ms to a run. The budget is 500 ms.** Fifty tool calls
through the sandbox boundary cost about 10 ms more than none, so well under 1 ms each;
that difference is the same size as the noise, so it is an upper bound, not a figure.

## How to read it

- The baseline costs the network and the Worker's start and nothing else. A case's added
  latency is its median less the baseline's.
- The noise is about 10 ms: one case came out faster than the baseline. Differences
  smaller than that mean nothing.
- The tool in these runs answers at once. A real tool's own time is not ExecWard's.

## Limits

- **No database in the measured path.** This route keeps its audit log in memory and has
  no broker, policy table, switches or quota counters. In production each run will write
  the audit log at least twice, and each tool call will read the policy and the switches
  and add to one or two counters. Each is a database round trip. This is the larger
  part of the real figure and it is not measured. It is owed once the database-backed
  path is wired into a served route.
- **One place, one time.** Measured from one machine to the nearest Cloudflare location,
  on one afternoon, with warm isolates. A cold start is not counted.
- **Not a load test.** Requests were sent one at a time.
- **A direct-call baseline for the same task was not run.** The 10% half of the budget
  needs one. With 3.0 s as the median direct-call run (task 0.2.6), 17 ms is under 1%.
